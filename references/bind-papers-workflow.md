# 跨学科批量「关联已有试卷」SOP

> 场景：把学校课程里已建好的试卷，批量挂到考试的对应学科上
> （考试 → 学科列表 →【学科】行 →「关联已有试卷」）。
> 本文是全流程作业标准。逐步命令见 `scripts/exam_papers.sh` 头部注释。

## 0. 一句话流程

```
【页面/登录异常时先 reset】 → snapshot（基线） → scan-courses（摸清各科可用的卷）
   → plan（出提案给用户看） → verify（只读核对卷名） → lint（写前自检） → 【用户批准】 → bind（写）
   → audit（逐格 diff 查副作用）
```

除 `bind` 外**全部只读**。生产站 `bind` 必须带 `--yes`。

> ⚠️ **写操作前先跑 `bash scripts/lint.sh`**。它抓的是两类"不报错也不崩、只静默出错"的问题：
> `$VAR` 后紧跟全角字符（`set -u` 下整批任务在第一条就死）、
> JS 模板串里的 `\d`（反斜杠被吃掉、页面正则全不匹配）。
> 2026-09-30 的 `bind` 就是栽在前者上：39 条一条没执行，但输出看起来像在跑。

```bash
export PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
SK=~/.workbuddy/skills/fuulea-teaching-cloud
bash $SK/scripts/exam_papers.sh lyyz reset          # ⓪ 页面卡死 / 登录反复超时时用
bash $SK/scripts/exam_papers.sh lyyz snapshot
bash $SK/scripts/exam_papers.sh lyyz scan-courses
bash $SK/scripts/exam_papers.sh lyyz plan       # 产出 proposals.json + plan_report.md
bash $SK/scripts/exam_papers.sh lyyz verify
bash $SK/scripts/exam_papers.sh lyyz bind --yes # ← 用户批准后才跑
bash $SK/scripts/exam_papers.sh lyyz audit
bash $SK/scripts/exam_papers.sh lyyz status     # 产物概况 + 扫描完整性
```

工作目录：`/tmp/fuulea/<别名>/papers/`，里面有：

| 文件 | 内容 |
|---|---|
| `matrix.jsonl` / `matrix_after.jsonl` | 考试×学科 绑卷矩阵（前 / 后） |
| `ch_<学科>.jsonl` | 该科课程 章节 → 试卷编号 |
| `ch_<学科>.meta.json` | 该科扫描是否可靠（`ok` / `unreliable[]`） |
| `scan_summary.json` | 9 科扫描完整性清单（`complete` 字段是闸门依据） |
| `proposals.json` / `plan_report.md` | 提案 / 缺口报告 |
| `verify.jsonl` | 逐条候选项卷名核对结果 |

## 1. 试卷编号从哪来

各学科教研在**课程**里按考试建了汇总课程，**一个章节 = 一场考试**，
章节内容里的 `#编号 满分N分 M道题` 就是该场该科的试卷编号。

登记在 `scripts/papers/subject-courses.conf`（`站点|学科|subjectId|courseId|课程名`）。
龙岩一中已登记 9 科；英语特别注意要选 `2024级英语考试汇总`（该学科下还有 2025级/2026级 两门）。

**换学校/换站点时要重新登记 courseId**（courseId 是站点级的，同一学校不会变）。
取法：`/course?schoolSubject=<subjectId>` → 点开 `2024级<学科>考试汇总` → URL 里的 `/course/<id>`。

## 2. 核心难点：章节名 ≠ 考试名

各学科命名风格**不统一**，所以不能靠字符串相等来配对：

| 学科 | 章节命名风格 | 例 |
|---|---|---|
| 生物 / 语文 / 英语 | 直接就是考试名 | `2024-2025第一学期高一第1次月考` |
| 化学 / 地理 / 历史 | 学年简写 + 上/下 + 年级 + 类型 | `24-25上·高一月考1_龙岩一中2027届…` |
| 物理 | 混合 | `024-2025第一学期高一期末考试`、`24-25学年第二学期高一第1次月考试卷` |
| 数学 | 真实卷名 | `龙岩一中2024—2025学年第一次月考高一数学试题` |

`plan_bindings.py` 的做法是统一归一成 **（学年, 学期, 年级, 考试类型）** 四元组再配对：

- 学年：`2024-2025` / `2024—2025` / `2024~2025` / `24-25` / 甚至 `024-2025`（原文缺字）都归一
- 学期：`第一学期` / `上学期` / `24-25上·`（⚠️ **上/下在间隔号前面**，别写反）
- 年级：`高一` / `高二` / `高三`
- 类型：`月考1` / `月考2` / `期中`（含"半期考"）/ `期末` / `开学联考`

**推不出四元组的章节一律不猜**，列入 `plan_report.md` 第三节交人工判断
（对应"缺数据绝不瞎编"原则）。

### 怎么确认归一化没搞错

用**本来就绑好的格子**做反向校验。例：化学课程章节 `24-25上·高一月考2` 取到卷 `81699915`，
而考试 29180（`2024-2025第一学期高一第2次月考`）本来就绑着 `81699915` ⇒ 解码方案正确。
本次用 24 个已绑格子校验，全部命中后才敢继续。

### 歧义章节的人工推断（2026-09-30 实证）

自动归一化是**故意保守**的：卷名里只要没写成「学年+学期+年级+考试类型」的紧凑格式就拒绝配对。
数学课程尤其严重——它的章节名是**真实卷名**（如 `龙岩市一级校联盟2024一2025学年第二学期半期考联考`），
语义信息齐全但格式不规则，于是 2026-09-30 一次就攒到 14 个未配对章节。

**不要靠放宽正则去"兼容"这些名字**（放宽必然误配，且错得无声无息）。正确做法是
**人工推断 + 走同一套只读复核与写护栏**：

1. 把「歧义章节」和「该科仍缺的考试」并排列出来（`ch_<学科>.jsonl` + `matrix.jsonl`）；
2. 逐条按 **学年 / 学期 / 年级 / 考试类型** 四要素**读语义**（不是字符串匹配）。
   注意 `2027届` = 2024 级：`2027届高一下学期` → 2024-2025 第二学期高一；
   `2027届高二上` → 2025-2026 第一学期高二；
3. 数量对账：**歧义章节数 == 该科缺口数**。对不上说明还有别的问题没发现，先查清楚；
4. 逐条落成一份独立提案 JSON（数组，字段同 `proposals.json`：`examId/examName/subject/chapter/paper`），
   用 `--from` 复用同一套流程：
   ```bash
   bash exam_papers.sh lyyz verify --from proposals_math_manual.json   # 只读核对
   bash exam_papers.sh lyyz bind --yes --from proposals_math_manual.json # 批准后写
   ```
5. 复核结果必须 **候选项不唯一 = 0 条** 才准绑；
6. 若某条只能靠**排除法**推定（名字里缺年级/学期），交付时要**显式标注它是排除法推的**，
   别让它看起来像确定性结论。

2026-09-30 实测：数学 11 个歧义章节 ↔ 11 个缺口，人工推断后 verify 11/11 唯一命中，
bind 11/11 成功，覆盖率 139/153 → 150/153。

## 3. 只读核对（verify）为什么必要

弹层的选择框：

- 按**编号**搜 → 唯一命中（我们走这条）
- 按**名称**搜 → **全库模糊搜，会返回别的学校的同名卷**
  （实测搜「第一次月考」返回过「2026-2027学年横岗高级中学高二第一次月考 - 历史」）

所以**永远用编号精确绑定**，名字只用来二次确认。
`verify_bindings.js` 会逐条打开弹层、输入编号、读出候选项卷名，并报告**候选项数量**——
若某条候选项 > 1，说明编号不唯一，必须人工确认后再绑。

## 4. 写操作的四道护栏

`bind_paper.sh` 已内建：

| 护栏 | 行为 |
|---|---|
| prod 站点 | 缺 `--yes` 直接退出码 4，不执行 |
| 幂等 | 该行已是同一卷号 → 跳过 |
| 卷名校验 | 候选项卷名与期望关键词不符 → 中止（防绑错） |
| 绑定后复核 | 重载页面轮询确认（最多 3 次），避免慢渲染导致假失败 |

`exam_papers.sh bind` 传的期望关键词 = **课程里的章节名**（试卷通常就按章节名命名）。
比对是去空白后的「互为子串 / 互为前缀」，既容忍截断显示，又不会把
「…第1次月考」和「…第2次月考」误判成同一个。

## 5. 收尾必做：逐格 diff（audit）

**不要只看改过的地方。** 把 `考试 × 学科` 全部格子重扫一遍，与基线 diff：

- 新增 == 提案清单（不多不少）
- 没有被解绑的格子
- 没有"本来就绑着、卷号却被换掉"的格子

任何一条不满足都算失败，必须人工复查。`diff_bindings.py` 会给出结论与退出码。

## 6. 两道自动化闸门（本轮沉淀的重点）

这两个坑的共同特征是：**流程"跑通了"，输出也像模像样，但结论是错的**。
所以都做成了硬闸门，宁可报错也不给错数据。

### 闸门 A：扫描数据完整性（防"半份数据出提案"）

**症状**：`scan-courses` 中途某科挂了（页面没渲染、树查询崩），
剩下的 `ch_<学科>.jsonl` 还在。`plan` 照样跑得出来，报告格式完美，
只是没扫到的那些学科全被写成「该科汇总课程无此场章节」——**静默少报**，
不看原始数据根本发现不了。

**处置**：

1. `scan-courses` 开跑前先 **`rm` 掉上次的 `ch_*.jsonl` / `ch_*.meta.json`**，
   杜绝过期数据当有效数据用；
2. 每科扫完写 `ch_<学科>.meta.json`，记录章节数与 `unreliable[]`
   （`name-mismatch` / `click-fail` 的章节）;
3. 汇总成 `scan_summary.json`（`complete` 字段）；
4. **`plan` 与 `bind` 在 `complete=false` 时直接拒绝执行**（退出码 5），
   并打印缺哪些学科、怎么修。确要用残缺数据必须显式加 `--allow-partial`，
   此时报告开头会加一行"⚠️ 本次数据不完整"。

> 对应原则：**缺数据绝不瞎编**。半份数据 + 乐观推断 = 比报错更危险。

### 闸门 B：浏览器会话健康（防"open 假成功"）

**症状**（实测反复出现，尤其在长时间自动化 / 开了多个会话之后）：

- `agent-browser open <url>` 回 `✓`，但 `get url` / `tab` 永远是 `about:blank`；
- `read` / `eval document.body.innerText` 拿到空；
- 诡异的是 `agent-browser console` 却能打印出**目标站**的日志
  （说明有两个"当前页"在打架）；
- `login.sh` 随之 3 次重试全超时，报 `LOGIN_FAIL: 页面未渲染出登录入口`。

**排查结论**（做过对照实验，别重复踩）：

- **不是**会话名的问题 —— 连字符 / 下划线 / 纯字母前缀都试过，无关；
- **不是**"别的 agent 抢会话"—— 单人单会话也能复现；
- **是 `~/.agent-browser/` 下的会话状态文件坏了**，且 **`close --all` 清不掉**：
  它回报 `✓ Closed session: X`，但 `X` 仍出现在 `session list` 里，
  下次用同一个名字启动会**继续命中那份坏状态**；
  换个新会话名就"好了"——这正是让人误判成"名字有问题"的原因。

**解法**：`scripts/browser.sh` 的 `hard_reset`

```bash
agent-browser close --all                    # ① 关会话（清不干净，只是第一步）
kill -TERM $(cat ~/.agent-browser/<会话>.pid) # ② 杀掉残留守护进程
rm -f ~/.agent-browser/<会话>.{pid,sock,target,stream,engine,version}  # ③ 删状态文件
# 或直接：bash scripts/browser.sh hard-reset
```

实测：彻底做完这三步，原本"怎么都不行"的会话名**立刻恢复正常**。
只删 `~/.agent-browser/` 下的会话状态文件，不动 `browsers/`（浏览器二进制缓存）和 `tmp/`。

**已封装**：

- `scripts/browser.sh hard-reset [--all]` —— 上面的三步（`--all` 清全部会话，谨慎）；
- `scripts/browser.sh open-checked <url> [选择器]` —— 打开后**确认真的渲染出来**
  （URL 不是 `about:blank`、body 非空、选择器存在），失败自动 hard-reset 重试；
- `login.sh` / `bind_paper.sh` / `papers/*.js` 全部改走这一层，不再裸 `open` + 固定 `sleep`。

**日常口令**：页面/登录不对，先 `bash scripts/exam_papers.sh <别名> reset`，再重跑。

## 7. 两个"看起来完全正常却是错的"的坑（务必记住）

这两个坑的共同特征是：**整批数据都错位了，但每一行看起来都合理**，
肉眼极难发现，只有用「已知答案」交叉校验才能抓出来。

### 坑 1：目录树里的装饰性节点 → 索引整体错位一位

章节页左侧目录是 `nz-tree`，里面有一个**没有 `title` 属性的可见装饰节点**
（与首章同坐标）。**取节点清单**和**点第 i 个节点**必须用**完全同一套过滤条件**：

```js
.filter(nd => nd.offsetParent && nd.querySelector('[title]'))
```

一旦两处过滤不一致，点到的永远是"上一章"。
后果：读到的卷号**整体错一位**，但每章都有卷号、格式也对，完全看不出来。

### 坑 2：切章后必须回验 `chapterName` 再读

点完章节后要用 URL 的 `chapterName` 参数确认真的切过去了（通常 2~3 秒内完成），
再读正文。否则会读到上一章的正文（同样表现为"整体错一位"）。

## 8. 其它已知坑

| 现象 | 原因 / 解法 |
|---|---|
| 弹层输入编号后不出候选项 | **必须按一次 Enter** 才触发搜索 |
| 点「确定」后列表没变化 | 页面原地刷新不更新 DOM，必须重新 `open` 同一 URL |
| "弹层关了"但没绑上 | 「确定」先做表单校验，**校验不过会静默不提交但弹层照关** → 必须回列表核对 |
| `bash: PAPER�: unbound variable` | 变量后紧跟全角字符（`$PAPER（`）被当成变量名一部分 → 一律写 `${VAR}`。**`set -u` 下会让整批任务在第一条就死掉且看起来像"跑了"**；跑写操作前先 `bash scripts/lint.sh` 扫一遍 |
| 该章显示「催录题目」 | 该场该科试卷未录入，**无法绑定**，需先催录入 |
| 考试列表只看到一半 | `/exam` 有分页，`scan_matrix.js` 会自动翻页 |
| **留证截图 before/after 逐字节相同** | 考试详情页学科行很长，靠后的学科（政治/历史/地理）在折叠线以下，而截图只拍**视口顶部** → 两张图都只拍到页面顶部的语文/数学行。**必须先 `scrollIntoView({block:'center'})` 再截**（`bind_paper.sh` 已修）；每条约再落一份 `-evidence.txt`，文本不受取景影响。2026-09-30 实测 39 条里 26 条中招 |
| 学校有的学科有多门汇总课程 | 如英语；必须按名字挑 `2024级…` 那门 |
| 某科扫描整门崩掉、后续科也报 `OPEN_FAIL no-row` | 树查询返回 `null` 未判空（v2 已修）；页面未渲染完就固定 `sleep`（v2 已改为轮询） |
| `zip`/`grep -P` 在 macOS 不可用 | 用 `python3` 或专用工具替代 |

## 9. 结果怎么读

- **可新增绑定**：有章节、有卷号、该考试该科却是未绑 → 可执行
- **仍缺 - 试卷未录入（催录题目）**：教研还没录卷，等录入后可再跑一遍流水线
- **仍缺 - 该科汇总课程无此场章节**：课程的场次覆盖本身不全，需要教研先建章节

后两类都不是"操作遗漏"，而是客观缺件。跑完 `plan` 直接把 `plan_report.md` 给用户即可。
